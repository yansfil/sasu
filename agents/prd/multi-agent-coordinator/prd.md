# PRD: hcoord 공통 에이전트 협업 서비스

## Goal

사용자는 부모 에이전트에게 자식의 관찰을 맡긴 뒤에도 대화를 이어가고, 답변이 필요한 요청과 놓친 확인을 공통 서비스에서 챙길 수 있다.
가칭 hcoord는 Herdr 위에서 관계·관찰·영속 요청·사람 개입을 제공하고, Sasu는 이를 사용하는 얇은 워크플로/스킬팩으로 전환하며 IDE는 같은 사실을 조회한다.

## Non-goals

- 수동 Task 원장·계획 진행률·작업 성공 판정은 만들지 않는다. 작업자가 매번 진척을 기록할 의무가 없으며, 계획 기반 진행도 수요가 구체화될 때 재검토한다.
- IDE 그래프 화면과 드래그 연결 편집은 제외한다. 관계 JSON과 이벤트만 제공하며 실제 IDE 화면 개발 단계에서 상호작용을 결정한다.
- 특정 외부 채널의 실서비스 연동은 제외한다. 어댑터 계약·연결 인터페이스·실행 가능한 예제로 확장 가능성을 제공하고 사용 채널이 정해지면 연동한다.
- 부모 부재 시 답변 직접 우회 전달이나 대체 중계자 배정은 제외한다. 미전달 보존·사람 알림·취소로 대응하며 복구 수요가 확인되면 재검토한다.
- 악의적 에이전트의 사람 사칭 방지, 다중 사용자 격리, 분산 daemon 복제, Herdr 실행기 재구현은 제외한다. 신뢰하는 한 사용자의 연결 범위에서 사용하며 비신뢰·다중 사용자·다중 권위 서버 수요가 생기면 보안/운영 계약을 다시 정한다.

## Behaviors

| # | 사용자가 관찰하는 행동 | 결정 |
| --- | --- | --- |
| B1 | `hcoord agent spawn --parent <id> --machine <id> --session <id> --name <name> -- <Herdr 생성 인자>`는 생성된 참여자 ID·계보·관찰 담당을 반환한 뒤 즉시 끝나며 자식 작업 완료를 기다리지 않는다. | D-03, D-16, D-23, D-36 |
| B2 | spawn의 `--no-watch`는 자동 확인만 끄며, 계보 조회와 이후 `request send` 저장·기한 추적은 계속 동작한다. | D-19, D-20 |
| B3 | `agent register`는 명시한 기존 실행을 연결하며 이름 충돌·사라진 실행·세션 교체는 실패 사유와 선택 가능한 정확한 대상을 보여주고 다른 실행으로 몰래 재연결하지 않는다. | D-03, D-23, D-07 |
| B4 | 생성·등록·관찰 연결 중 일부만 성공하면 확보한 ID와 미완료 단계를 반환하고 같은 intent key 재시도는 기존 결과를 재사용하며 생성 여부 불명 상태에서 새 자식을 중복 생성하지 않는다. | D-16, D-03, D-07 |
| B5 | `watch start <target> --observer <id> [--interval 5m]` 이후 부모는 사용자와 계속 대화한다; 기한이 오면 대상별 미확인 회차에 연결한 확인 요청 하나를 저장해 관찰자에게 안전 전달하고 기존 회차가 미확인이면 새 요청 대신 최신 관측을 합친다; 이 요청도 생성 후 15분/30분 정책을 따른다. | D-16, D-21, D-33, D-35 |
| B6 | `watch check <target> --cycle <id>`는 담당자가 실제 확인했다고 명시한 해당 회차만 확인 처리하며 전송 수락·조회·다른 자식 확인으로 대신 처리하지 않는다. | D-01, D-21, D-07 |
| B7 | 작업 중·idle·종료 사실, 연결 불명, 확인 지연을 분리 표시하며 활동 없음이나 시간 초과만으로 실패/성공 판정 또는 관찰 자동 종료를 하지 않는다; 일반 상태 변화는 최신 사실만 갱신하고 별도 wake를 만들지 않으며 연결 불가도 관찰 불가 표시와 기존 확인 요청 맥락을 갱신해 다음 정기 확인에서 다룬다. | D-17, D-18, D-33, D-35 |
| B8 | `watch stop <target>`은 현 담당자 또는 사람이 명시적으로 종료하며 자식 실행·계보·열린 요청을 지우거나 종료하지 않는다. | D-18, D-19, D-22 |
| B9 | `watch assign <target> --observer <id>`는 현 담당자/사람만 가능하며 경쟁 요청 중 하나만 적용하고 충돌자는 현재 담당을 확인해 다시 선택한다; 담당 부재는 사람 inbox에 남고 임의 대체자를 고르지 않는다. | D-21, D-22, D-32 |
| B10 | `request send --from <id> --to <id 또는 human> --body <내용> [--waiting] --intent <key>`는 본문·필요 맥락·담당을 저장한 후 요청 ID를 반환하며 저장 실패를 성공으로 알리지 않는다; 답변 없는 정보 알림은 요청 응답 의무를 만들지 않는다. | D-07, D-12, D-24 |
| B11 | 수신자가 작업 중이거나 사람이 입력 중이면 전달 대기와 이유를 표시하고 안전한 제출 순간에 실행 신원과 입력 guard를 다시 검증한다; guard 미지원/확인 불가는 보류하며 일반 prompt로 우회하지 않는다. | D-01, D-04, D-23 |
| B12 | 요청 생성 후 미응답 15분에 한 번 재알림하고 30분에 같은 요청을 사람 inbox로 올리며 작업 실패로 표시하지 않는다; 관찰 5분과 두 요청 기한은 설정 가능하고 설정값을 조회할 수 있다. | D-13, D-33 |
| B13 | `request show <id>`는 질문·담당·답변 원문·기록자·대기 이유·전달 시도·다음 조치를 보여주며 부모가 직접 답하거나 `request escalate <id> --to human`으로 같은 요청을 올릴 수 있다. | D-05, D-10, D-12, D-26 |
| B14 | 사람은 `hcoord inbox`로 확인하고 `request reply <id> --body <답변> --as human`으로 답하며, 대화 에이전트도 실제 받은 답변만 대신 기록한다; 실제 응답자와 기록 주체를 구별하고 임의 대화를 승인으로 추정하지 않는다; 여러 열린 요청 중 연결 대상이 불명확하면 기록하지 않고 요청 선택을 물어 명시적으로 연결한 뒤 저장한다. | D-05, D-06, D-11, D-29, D-32 |

## Technical structure

`Sasu 스킬팩 / hcoord CLI / IDE 클라이언트 → 동일 API → 단일 coordinator daemon·영속 저장소 → Herdr 어댑터 / 사람 채널 어댑터` 구조다.
참여자는 영속 ID와 `(machine, session, runtime instance)` 바인딩을 갖고 pane/name은 표시·현재 라우팅 자료로만 쓰며, 생성 계보와 세대가 있는 관찰 배정, 대상별 확인 회차, 요청과 전달 시도를 분리한다.
가정: 단일 writer 트랜잭션 저장소에서 요청 변경과 outbox를 함께 확정하고 intent key·관찰 세대·회차로 경합을 제어하며, 조회는 snapshot과 cursor를 제공한다.
요청의 응답 상태는 `open → answered 또는 canceled`, 담당 변경은 같은 요청 안에서 이루어지고 각 전달은 `pending/deferred → accepted → acknowledged` 또는 `unknown/failed`로 별도 기록한다.
사람 답변의 중계 대기가 남으면 answered여도 미해결이며 30일 정리 대상이 아니고, answered에 대한 중복/경쟁 답변은 기존 답변을 덮어쓰지 않으며 취소 후 답변은 감사 이력만 추가한다.
가정: 버전 있는 JSON API를 macOS 사용자 로컬 socket·Windows 사용자 제한 named pipe로 제공하고 원격 CLI는 기존 SSH 인증의 stdio bridge를 통해 동일 daemon에 접속한다; Herdr의 saved-machine 라우팅을 coordinator API로 오인하지 않는다.
macOS 로그인 연동과 Windows 로그인 연동, 알림, 경로, 프로세스 소유권을 OS 어댑터로 분리한다; 첫 배포의 확정 범위는 공통 코어와 양 OS 연동 경계이며 플랫폼별 기능 지원은 실제 구현·검증 결과로 제한하고 두 OS 전체 연동의 동시 출시를 추가 약속하지 않는다.
원격 실행 호스트는 Herdr가 실제 지원하는 범위이고 Windows를 원격 호스트로 지원한다고 확대하지 않으며, macOS 전용 API를 공통 코어의 필수 전제로 넣지 않는다.
예: `hcoord agent spawn --parent p1 --machine m1 --session s1 --name worker -- ...` 뒤 `request send --from c1 --to p1 --body '선택이 필요합니다' --intent q1`, `request escalate r1 --to human`, `request reply r1 --as human --body 'A로 진행'`, 부모의 `request relay r1 --body 'A로 진행'`, 자식의 `request ack r1` 순서이며 어느 단계도 작업 성공을 뜻하지 않는다.
가정으로 적은 API/저장/인자 선택은 이 PRD 검토에서 변경 가능하며, 별도 Task 상태·분산 broker·Sasu 역할 타입은 도입하지 않는다.
`watch check`, `request ack`, intent key와 자원 상한은 D-01/D-07/D-21을 구체화한 작성자 기술 가정이며 사용자 승인 사실로 취급하지 않는다; engineering 원칙 4~15와 process practice에 따라 영속 mail/비종결 ACK 선례를 참고하고 실패·중복·자원 수명을 통제한다.
현재 저장소 기본값은 PR 배송, main 기준, worktree 사용, CI watch 꺼짐이며 이번 문서 작성이 외부 배송을 승인하지는 않는다.

## Risks

- 현재 설치 Herdr 0.9.1의 도움말/번들 스키마에서는 atomic input guard를 확인하지 못했고 별도 checkout에만 계약이 보인다. 실행 서버 capability와 제출 순간 보호를 검증해야 하며 미지원이면 B11대로 보류한다; 입력 안전성을 확보하지 못한 배포를 왕복 흐름 완료로 주장하지 않는다.
- 신뢰 기반 사람 기록은 보안 승인 증명이 아니다. 임의 배포·삭제·외부 전송 권한을 이 요청 모델로 새로 부여하지 않으며 실제 채널 자격증명과 실서비스 연결은 이번 범위 밖이다.
- Windows/원격 지원은 소스 조사만으로 검증되지 않았다. 각 지원 OS의 실제 시작·중지·알림·복구와 원격 왕복을 확인하고 지원 범위를 배포 문서에 명시해야 하며 현재 구현·호환 시험 완료 주장은 없다.
- 출시 수용 근거는 실제 Sasu의 대화 중 백그라운드 관찰, 사람 응답의 자식 반환, 입력 중 보류, 단절·재시작 후 보존 및 중복 감독 방지 흐름이다. 시험은 격리된 사용자 데이터/테스트 세션을 사용하고 실사용 pane·launchd·원격 머신에 무단 입력·재시작하지 않는다.
- 외부 전달의 exactly-once 처리와 실제 작업 성공은 보장하지 않는다. 결과 불명·부모 부재·알림 실패는 사람에게 보이며, 자원/디스크 한계 시 미해결 데이터를 지우는 대신 실패를 반환한다.
- 별도 사용자 계정·구매·자격증명은 PRD 검토에 필요 없다. 문서 승인과 구현 시작은 아직 대기이며 저장소 PR 기본값은 push·PR 생성·병합 승인이 아니다.
