# Agent Memory Systems — 리서치 저널

질문: 에이전트 메모리 시스템의 큰 구조 + 2025~2026 트렌드/연구.
동기: sasu 하네스에 "기억할 만한 게 있으면 물어보는" 훅을 붙이려는 중.

## axis-4 산업 구현체 + 벤치마크 (완료)

### 제품들의 실제 동작
- **ChatGPT**: saved-memories 목록 방식을 폐기하고 "memory summary"(연속 갱신 요약)로 전환.
  벤더 자백: "이전 방식은 낡아버렸고(stale) 사용자가 직접 관리해야 했다. 기억끼리 모순되기도 했다
  ('마라톤 훈련 중' vs '발목 삠')". → append-only 사실 목록은 썩는다.
  물어보지 않고 자동 저장. 서버 저장. 계정 전역. https://help.openai.com/en/articles/8590148-memory-faq
- **Claude Code**: CLAUDE.md(사람이 씀) + auto memory(모델이 씀) 2종. 
  MEMORY.md 인덱스 200줄/25KB 하드 예산 - 넘으면 쓰기는 성공하되 에러로 재작성 지시(코드로 강제).
  frontmatter `modified` 타임스탬프. git 저장소 단위로 키잉(워크트리 공유). 머신 로컬.
  공식 문서 자백: "context이지 강제 설정이 아니다. 무조건 막으려면 PreToolUse 훅을 써라."
  https://code.claude.com/docs/en/memory
- **Cursor**: 배경 모델이 제안 → **사용자가 승인해야 저장**. 주요 제품 중 유일한 인간 게이트.
- **Windsurf/Devin**: auto-memory를 **폐기**. "새 탭의 기본 에이전트인 Devin Local은 메모리를 저장하지 않는다.
  의존하던 것은 skills로 옮겨라. 권장: 자동 생성 메모리 대신 Rule이나 AGENTS.md에 써라 -
  버전 관리되고, 팀과 공유되고, 활성화를 명시적으로 제어할 수 있다."  ← 자동 메모리를 출시했던 벤더의 후퇴
- **GitHub Copilot Memory**: 업계 최고의 staleness 방어. 사실을 **근거 코드 인용과 함께 저장**하고,
  쓸 때마다 현재 브랜치에 대해 인용을 재검증. **검증된 사실만 사용.** 미사용 사실은 **28일 TTL**로 자동 삭제.

### 벤치마크는 대부분 못 믿는다
- **LOCOMO** (가장 많이 인용됨, 가장 망가짐): Penfield Labs 감사 결과 1,540문항 중 **99개(6.4%)가 채점 오염**.
  (ML 벤치마크 평균 라벨 오류 3.3%의 두 배) 24문항은 화자를 잘못 귀속 - 화자 추적이 정확한 시스템이 오히려 감점.
  완벽한 시스템의 이론적 상한 ~93.6%. **더 큰 문제는 심판**: gpt-4o-mini 심판이 의도적으로 틀린 답을
  **62.81% 통과**시킴. 특히 "주제는 맞고 디테일은 다 틀린" 답 - 정확히 약한 검색의 실패 양상 - 을 통과시킴.
  → **63% 미만의 점수 차이는 해석 불가.**  https://penfieldlabs.substack.com/p/we-audited-locomo-64-of-the-answer
- **LongMemEval-S**: ~115K 토큰이라 요즘 컨텍스트 창에 통째로 들어감. "메모리 테스트가 아니라 컨텍스트 창 테스트."
- **ConvoMem** (Salesforce, 2511.10523): 가장 아픈 결과. 단순 full-context가 **70-82%**,
  Mem0 같은 RAG 메모리 시스템은 **30-45%**. 대화 150개까지는 그냥 다 넣는 게 낫다.
- **BEAM** (10M 토큰): 유일하게 포화 안 됨. mem0가 LOCOMO 92.5 / LongMemEval 94.4인데 **BEAM-1M 64.1, BEAM-10M 48.6**.
- **벤치마크 전쟁**: 같은 시스템(Zep)이 84% → 75.14% → 65.99% → 58.44%로 채점됨. 두 벤더가 서로 하네스를 조작했다고
  재현 가능한 케이스를 걸고 고발 중. mem0 독립 재현 시도는 논문 0.68 대비 **0.20** 나옴(mem0 측이 버그 인정, 논문 수치는 재계산 안 함).

## axis-3 핵심 난제 — salience / 망각 / 충돌 (완료)

### ★ 크럭스 답변: "자동 추출의 오탐률에 증거가 있는가?" → 있고, 나쁘다

세 갈래 독립 측정이 전부 같은 방향:

**(1) HaluMem** (2511.03506) — 유일한 연산 수준(operation-level) 벤치마크. 쓰기 정확도를 직접 잼.
  - Mem0(Medium): 16,291개를 쓰는데 **약 39%가 쓰레기**, 정작 중요한 건 42.91%만 포착
  - Memobase: 17,081개 쓰고 **약 68%가 쓰레기**
  - MemOS(Long): 99,462개 쓰고 **약 56%가 쓰레기** (과잉 추출로 F1만 이김)
  - Mem0의 recall은 1M 토큰 규모에서 **3.23%로 붕괴**
  - FMR(어시스턴트가 말했을 뿐 사용자가 확인 안 한 걸 사용자 사실로 저장): 최악 80.78%
  - ⚠ 이해충돌: 저자가 MemTensor 소속이고 그 회사 제품 MemOS가 1위. 단 MemOS가 못 이기는
    Accuracy/FMR 열이 오히려 신뢰도 높음.

**(2) GovMem** (2607.02579) — 사람이 직접 판정한 쓰기 경로 연구.
  - 합성 데이터 기준선 false promotion rate **0.597**
  - 실제 트레이스, 출처+범위만 볼 때 **0.371**
  - ★ **실제 코딩 에이전트 메모리 후보 133개를 사람이 판정한 결과, 자동 승격이 안전한 것은 0개.**
    검증 게이트를 통과한 11개도 전부 보일러플레이트/공용 툴 산출물/파일 덤프/재사용 불가 디버깅 트레이스로 기각.

**(3) 결과로 측정** (2505.16067) — 실제 에이전트 4종 × 쓰기 정책 5종.
  - **"전부 쓰기(add-all)"가 "100개짜리 고정 메모리(절대 안 씀)"보다 4/4 전부 나쁨**
  - EHRAgent(의료 추론): add-all 13.05%(2,411건) vs 엄격 게이트 **38.50%(1,012건)**.
    **더 적은 메모리로 3배 정확도.**
  - 기제: experience-following → 나쁜 기록이 복제·증폭되어 다시 쓰기됨(error propagation)
  - 처방: **"미래 과제 평가가 저장된 메모리의 공짜 품질 라벨"** — 쓰기 시점이 아니라 사후 결과로 판단

### salience 기제 자체는 검증이 없다
- **Generative Agents의 1~10 중요도 점수**: 원 논문이 정확도를 **한 번도 측정하지 않음**.
  근거는 한 문장 - "LLM에 정수로 물어보면 효과적임을 발견했다". ablation도 중요도 점수를 건드리지 않음.
  가중치 α는 전부 1로 두고 튜닝 안 함.
- ~~쓰기 시점 정적 중요도는 효용과 ρ=0.00~~ ← **wave3에서 정정: 대조군이 상수 0.5라 산술적 0. 실제 중요도 휴리스틱은 하나도 안 돌렸음. 순수 시뮬레이션.** 제대로 된 판본은 SPW-Gate.
  결과 기반 갱신은 ρ=0.89. → 한 번 매기고 안 고치는 점수는 순위 정보가 아예 없다.
- **Titans의 surprise**: ablation에서 **weight decay(망각 게이트)가 surprise보다 기여가 큼.**
  즉 "무엇을 담을까"보다 "무엇을 버릴까"가 더 중요.
- **EM-LLM의 Bayesian surprise**: 사람이 라벨링한 팟캐스트 경계와 매우 유사 → surprise는
  **"에피소드 경계가 어디인가"의 좋은 신호**. 하지만 **"보관할 가치가 있는가"의 신호는 아님**.
- ★ **True Memory** (2605.04897) 저자 자백:
  "인코딩 게이트(novelty/salience/prediction error)는 **보고된 모든 벤치마크 수치에서 꺼둔다.
  현재 평가 도구는 총 recall만 보상하고 선별적 수집을 채점할 수 없기 때문이다.**"
  → **이 분야에는 쓰기 결정을 채점할 계측기가 없다.**

### "실패에서 배운다"의 부메랑 — 우리 설계에 직결
**Honest Lying: Memory Confabulation in Reflexive Agents** (2605.29463)
- Reflexion은 에이전트가 자기 실패를 진단할 수 있다고 가정한다. 대개 못 한다.
- **ALFWorld의 16개 환경에서, 121개 reflection 중 올바른 대상 물체를 언급한 것이 0개.**
  환경이 매 시도마다 올바르게 리셋되는데도 틀린 해석을 확신하며 계속 씀.
- 처방: 개방형 자기진단을 **트레이스에서 기계적으로 뽑은 실패 신호**로 대체 →
  올바른 대상 언급 **0% → 86%**, 반복률 0.64 → 0.10
- ★ 교훈: **"내가 왜 실패했는지"에 대한 LLM 자신의 서사는 나쁜 salience 신호다.
  트레이스에서 기계적으로 유도한 신호가 훨씬 낫다.**

### 통합(consolidation)은 현재 순손실
**Useful Memories Become Faulty When Continuously Updated by LLMs** (2605.12978)
- ARC-AGI 19문제: 메모리 없이 **100%** → **정답까지 주면서** 통합을 거치면 **54%**
- 실패는 경험이 아니라 **통합기(consolidator)에 있다**
- 원시 롤아웃을 그냥 덧붙이는 episodic-only 대조군이 ACE/AWM/Dynamic Cheatsheet와 대등
- 에이전트에게 선택권을 주면 **원시 에피소드를 보존하고, 강제 통합 대비 정확도가 2배**
- 직격: "최근 에이전트 메모리 시스템들(CLIN, AWM, Dynamic Cheatsheet, ACE)은 매 상호작용마다
  갱신하는 설계를 쓰며 통합 단계를 최악이라도 중립으로 취급한다. 우리 결과는 그 가정을 반박한다."

### 충돌 해결: 이중시간 모델도 LLM이 판정하면 소용없다
**MemoryAgentBench** (2507.05257, UCSD, 벤더 무관) FactConsolidation-SingleHop:
  - **Zep(이중시간 그래프로 설계된 바로 그 시스템) 7.0%** ← 표에서 최하
  - BM25 48.0%, HippoRAG-v2 54.0%, 그냥 GPT-4o 롱컨텍스트 **60.0%**
  - ★ Mem0(21.1), Cognee(20.6), Zep(24.0), MemGPT(28.3) 전부 **자기 백본(42.2)보다 낮음**
**Don't Ask the LLM to Track Freshness** (2606.01435):
  - **코사인 유사도로는 모순과 중복을 원리적으로 구분 못 함.** 값만 뒤집힌 모순이 오히려 더 유사함.
  - 결정론적 max(serial) 파이썬 한 줄 → FC-SH **78.0~94.8%** (기존 상한 7% 대비)
  - 단 버전 구조가 있는 데이터에 한함. 비구조 데이터에선 LLM 판정과 무승부.

### 무한 append가 왜 실패하는가 — 코딩 하네스 직결
**Why Does CLAUDE.md Keep Growing? Catastrophic Remembering** (2608.11095)
- 1,867개 저장소 / 247,694개 지시문 생애 추적
- 프롬프트가 **무한 성장. 생애 동안 +226%**, 커밋당 순 +4.9줄
- ★ **지시문은 오래될수록 삭제될 확률이 낮아진다** (log-hazard -0.032/commit). 감쇠의 정반대.
- 원인: 추가는 항상 싸지만, **근거(rationale)가 사라진 지시문을 회귀 없이 지우는 비용은 O(2^|D|)**
- ★ **해법은 주석이다.** 잠재 근거를 담은 주석이 초과 지시문의 **99.3%를 제거**(+211.3% → +1.4%),
  실제 지시 준수도 최대 **+23.1%**
- 마지막 문장: "영어가 새로운 코드라면, 왜 우리에겐 아직 주석이 없는가?"
- → 이 저장소 CLAUDE.md의 "why를 코드 옆에 기록하라"가 실증적으로 뒷받침됨.
  주석은 위생이 아니라 **삭제를 가능하게 만드는 장치**.

### 이겨야 할 기준선이 창피하다

### 아키텍처 5패턴과 실측 트레이드오프
**(a) RAG/벡터** - 확장 쉽고 원본 보존. 단 검색 품질에 인질, **저품질 항목이 노이즈로 판단 저해**
**(b) 지식그래프** - ★ HippoRAG 2 초록의 결정적 문장:

   **더 기본적인 사실 기억 과제에서는 표준 RAG보다 성능이 상당히 떨어진다.**"
  → **그래프 메모리는 공짜가 아니다. 다중홉을 얻고 단순 사실 회상을 잃는다.**

  쓰기에서 깨진 JSON이 나와 장기기억이 조용히 오염됨. append-only는 이 문제가 없음.
**(c) 요약/압축/계층** - MemGPT: main context(=RAM, 시스템/워킹/FIFO) + external(=디스크),

   - **context collapse / brevity bias** (ACE 2510.04618): 반복 재작성이 디테일을 침식.
     처방은 통째 재작성 대신 **작은 증분 편집**
   - ★ **compaction cliff** (2608.22752): "안전 규칙과 에피소드 로그가 같은 토큰을 두고 경쟁한다.
     예산이 넘치면 **둘 다 같은 비율로 요약되는데, 정확한 문구가 필요한 건 규칙뿐이다.**
     20개 프로덕션 설정에서 Claude Code의 /compact는 **1회 압축 후 안전 규칙의 53%,
     5회 후 10%만 보존**했다." 처방: 지식 타입별로 다른 보존 정책(Knowledge Triage)
**(d) 파라미터 내재화** - Memory Layers(FLOPs 안 늘리고 파라미터만), Titans(테스트 시점에
  자기 가중치를 갱신, surprise = 입력에 대한 손실의 기울기). 갱신 비용이 크고 망각 위험 →
  "대규모 도메인 지식·과제 사전지식에 적합, 개인화된 짧은 메모리엔 부적합"
**(e) Memory OS** - MemOS의 MemCube = 내용 + **출처·버전 메타데이터**, 타입 간 이주 가능
  (자주 쓰이는 평문이 파라미터로 승격). RAG를 "생애주기 통제 없는 무상태 임시방편"이라 규정.
  ★ 실측 대가: MemoryOS 턴당 지연 **32초 이상** (SimpleMem 1.1초, Full Context 1.7초).
  "엄격한 계층 페이징은 대화형 환경에서 비실용적"

### 각 시스템의 직관 (한국어 설명용)

- **MemGPT** = LLM에게 스왑 파일을 주고 페이지 교체를 LLM 본인에게 시킴. 70%에서 memory pressure 경고.
- **MemoryBank** = 안키(간격 반복)를 그대로 이식. 꺼내면 S+1, t 리셋.
- **Reflexion** = 오답노트. 가중치 대신 노트를 다음 시험지 옆에 둔다.
- **A-MEM** = 제텔카스텐 카드 상자. 새 카드가 옛 카드의 메모까지 고쳐 씀(memory evolution).
- **Mem0** = 비서가 인덱스카드를 갱신. **ADD/UPDATE/DELETE/NOOP을 LLM이 직접 고름.**
  Generative Agents가 append-only였다면 Mem0는 **파괴적 갱신(DELETE)을 도입**한 것이 차이.
- **Zep** = 회계 원장. 지우지 않고 **만료**시킨다. 엣지마다 타임스탬프 4개
  (시스템이 안 시점 2개 + 현실에서 참이었던 구간 2개) → "작년 6월 기준으로는 뭘 알고 있었나"를 되물을 수 있음.
- **HippoRAG** = 머릿속 색인 카드. 사실이 아니라 **어디에 무엇이 있는지의 색인**을 갖고,
  하나 떠올리면 연결된 게 딸려옴(Personalized PageRank).
- **Titans** = **"놀라면 기억한다, 그리고 놀람에는 여운이 있다."** surprise = 입력에 대한 손실의 기울기,
  모멘텀 SGD와 형태가 동일. 망각 게이트 α_t로 지운다.
- **MIRIX** = 회사 파일링 시스템. 6개 서랍(Core/Episodic/Semantic/Procedural/Resource/Knowledge Vault)에
  접수 담당자가 분류해 넣음.
- **LangMem의 핵심 프레이밍** = **"지금 받아적을까(hot path), 퇴근하고 정리할까(background)"**.
  이 이분법이 Letta sleep-time, Mem0 비동기 요약, ChatGPT/Claude 저장 시점 설계를 전부 설명.

6. **국소적 유지보수가 전면 재조직보다 비용 효율적.**

### ★ 독은 주입이 아니라 추출(extraction)이다

### ★ 실패를 기억하는 게 도움이 되는가는 "표현 형식"의 성질이다

|---|---|---|---|

  "실패를 기억하면 도움이 되는가"는 실패의 성질이 아니라 **표현의 성질**이다.

### ★ 핵심 조화: 한 번 추상화는 좋고, 반복 재추상화는 나쁘다

## wave3 쓰기 결정을 채점하는 계측기 (완료) — ★ 설계 질문에 직접 답함

**판정: 구멍은 실재하고, 2026년 논문 몇 편이 부분적으로 메웠다. 단 메운 것들 전부가

모두가 보고하는 공개 벤치마크에서는 여전히 "많이 저장할수록 이긴다".**

### ★ 시험지가 "얼마나 안 적었나"를 안 묻는다
LoCoMo, LongMemEval, MemBench, ConvoMem, AMA-Bench, MemoryAgentBench, BEAM — 전부
"나중에 물어봤을 때 맞히는가"만 점수를 준다. 확인 결과:
- **MemBench의 "efficiency"는 메모리 연산 수가 아니라 벽시계 지연(초/연산)**. 오히려 무분별한 쓰기에 유리.
  `FullMemory`가 WT <0.001초로 "가장 효율적".
- **MemoryAgentBench의 Selective Forgetting은 갱신 지표**이지 쓰기 거부 지표가 아니다.
- **ConvoMem의 Abstention은 답변 측 기권**("모른다"를 정답 인정)이지 쓰기 측 거부가 아니다.
→ 그래서 Sauron Labs가 프로덕션 게이트를 벤치마크에선 껐다(τ = −∞).
  부정직해서가 아니라 **켜면 손해 보는 시험이라서.**

### ★ HaluMem의 FMR만이 유일한 진짜 "거부된 쓰기" 지표 — 단 범위가 좁다
- **Memory Accuracy는 선별성 지표가 아니라 충실성 지표.** 잡담에서 뽑았어도
  트랜스크립트가 뒷받침하면 만점. **날조는 벌하지만 과잉 포함은 안 벌한다.**
- **Target Memory Precision은 precision이 아니다.** 분모가 이미 gold와 필드 매칭된 부분집합.
  아무것과도 안 맞는 추출물은 그냥 제외된다. **구조적으로 과잉추출을 벌할 수 없다.**
- **FMR만이 진짜**: 적대적으로 주입한 distractor(사용자는 침묵하는데 AI가 자연스럽게 쓰는
  거짓 유사 메모리)를 **저장하지 않는 결정**을 센다.
  → 그러나 그 부정 클래스는 "확인 안 된 AI 발화" 하나뿐. **"참이고 사용자가 확인했지만 무가치한 것"**을
    재는 지표는 어디에도 없다.
- ★ 구조적 관찰: **MemOS가 이기는 유일한 지표(F1)가 과잉추출에 수학적으로 눈먼
  Target Precision을 정밀도 항으로 쓴다.** MemOS는 gold 14,948개에 대해 71,793개를 쓰고,
  필드 매칭된 부분집합만 해도 45,190개(gold의 3.0배)다. **중복을 벌하는 지표는 이 분야에 없다.**

### ★★ A-MAC — admission 결정 자체를 precision/recall/F1로 잰 유일한 논문

### ★ 심판의 질이 곧 삭제 능력이다 — Blind Curator (2607.07436, 유일하게 3시드+표준편차)
스킬 은퇴(retirement)가 라이브러리 비대를 막는데, 그 보장은 **편향 없는 기여도 추정기**를 전제한다.
단위 테스트·정확 일치는 만족하고, 참조 없는 과제의 LLM 심판은 아니다 —
그 오차가 **비대칭(거짓 통과)**이라 백색잡음이 아니기 때문.
**정리: 대칭 잡음 ρ는 은퇴 기능을 살려두지만, 거짓통과율이 (1−τ)/2를 넘으면
어떤 양의 데이터로도 기여도 기반 은퇴가 복구 불가능해진다.** τ=0.10이면 절벽은 q=0.45.
★ 그리고 **어떤 집계 지표에도 안 나타난다** — "비활성화된 큐레이터는 침묵한다".
→ 테스트가 통과/실패를 말해주는 코딩 영역이 유일하게 믿을 만한 무대인 이유.

### ★ CLAUDE.md는 왜 계속 커지는가 — 정확한 실험 설계 (2608.11095)
- 이론: 삭제의 정직한 검증은 **O(2^|D|)** (중복 때문에 하나씩 빼보는 게 안 통함).
  **왜 넣었는지(latent rationale)를 알면 O(1)**로 붕괴. 그런데 그 이유는 문장보다 빨리 사라진다.
  → 유량 균형에서 **|D_∞| = A / (ρ̄(a)·s) → ∞**. 상수 추가율과 고정 제약에서도 초과 크기가 발산.
- 현장: 1,867 저장소 / 247,694 지시문 생애. 중앙값 파일 39개 지시문. 평균 **+226%**.
  ★ **삭제의 76.8%가 통째로 갈아엎는 한 커밋에서 나온다.** 갈아엎은 뒤 10커밋 내 91.5% 복귀,
  그리고 **더 빨리 자란다(4.1%→4.9%/커밋)**. "하나를 지우려면 이유가 필요하고, 전부를 지우려면 필요 없다."
  ★ 기제 식별: 로그위험 기울기 **−0.032/커밋** → 낡음(staleness) 가설 반증(낡을수록 오히려 안 지워짐).
  다저자일수록 더 안 지워짐 **β=−0.021, z=−11.7** → 불완전 회상 가설만 예측하는 결과.
- ★ 주석 실험의 정확한 조건 — **다섯 가지가 동시에 성립할 때만 효과가 난다**:
  모호한 판정 / 통과는 검열 / 제약 식별자 비공개 / 간결성을 요구하지 않는 목표 / 지평 10단계 이상.
  "검증기 명세를 전부 공개하면 무주석 팔도 초과 크기 +3.0%에 그치고 효과가 완전히 사라진다."
- 주석의 정의: **실행자에게는 안 보이고**(하네스가 코드로 제거) **다음 유지보수자에게만** 보임.
  지시문 한 줄에 붙고, 추가할 때 한 번 쓰고 **수정 불가**, 1,024자 제한, 삭제에는 주석을 못 붙임.
  4개 필드 필수: 라운드 번호 / **인용된 실패 서술 + 몇 라운드째 재발 중인지** /
  **이미 반증된 접근의 계보** / 삭제하는 지시문의 원문 인용.
- 결과 (T=51, 184 세계): 무주석 초과 **+211.3%** → 정보성 주석 **+1.4%** = **99.3% 제거**,
  만족도는 양쪽 44.0%로 동일(통계적으로 구분 불가).
- ★ **페이로드 ablation**: 결과 없이 시도 서사만 담은 주석은 **+8.8로 최악**(무주석보다 나쁨) —
  "후임자에게 검증되지 않은 전제를 넘겨주는 것". 재발 횟수 필드를 빼면 효과의 37% 상실.
- ★ **강한 유지보수자일수록 더 심하게 래칫하고 주석이 더 많이 돕는다**:
  무주석 최종 크기 Haiku 1.68 → Sonnet 3.07 → **Opus 6.72**. 최상위 티어에서 주석은 파레토 개선.
- ⚠ 저자 자신의 윤리 경고: **"주석을 쓰는 것은 아무것도 제거하지 않으므로 안전하다.
  그것에 따라 행동하는 것은 안전하지 않다."** 정보성 주석 팔은 **12.1%의 세계에서 프롬프트를 통째로 비운다**
  (다른 팔은 2.4%/1.1%), 그리고 그 세계들에서 만족도는 오히려 낮다.
- ⚠ 실제 프롬프트 전이 실험(WildIFEval)은 **LLM 심판 채점**이고, 심판을 바꾸면
  **+11.6pp → +7.8pp, 95% CI가 0을 포함**한다. 깨끗한 결과는 IFEval 쪽 절반뿐.
