### Follow-up improvements

- `index.json` (`cli/src/supervisor/index.ts`) enrolls arbitrary absolute `statePath` values from any repo on the machine with no ownership/path scoping. Not exploitable today (wakes still require live session/terminal match against the recorded `ObserverIdentity`, and the file lives under the invoking user's own `~/.sasu`, so it's the same trust boundary as any other locally-run process), but there is no defense-in-depth check that `statePath` sits under a project the CLI itself manages. If a future feature lets state.json content or `statePath` come from a less-trusted source (e.g. shared/multi-tenant machine, or a path a run's own PRD/agent content could influence), this becomes a real cross-run read primitive. Consider validating `statePath` is under an expected `agents/**` root before enrolling.
- `promptAgent`/`getAgent` (`cli/src/implement/herdr.ts`) run `herdr agent prompt <target> <text>` via `spawnSync(..., shell: false)`, so wake text (including PRD slug, reasons, and detail strings built from `state.json`/git content) reaches the pane only as literal keystrokes with no shell parsing — good. Worth a one-line comment near `renderWake`/`promptAgent` making explicit that `text` is never shell-interpreted, since a future refactor to `execSync`/string concatenation would silently reintroduce injection.
- LaunchAgent plist (`cli/src/supervisor/launchd.ts`) inherits `PATH` from whoever ran the installer, embedded verbatim (XML-escaped) into the plist and used for every unattended tick going forward. This is intended per the file's own comment (herdr/git need to be reachable), but it does mean any directory on the installer's PATH at install time gets 30-second-interval code execution as the user indefinitely. Reasonable given the current single-user design; if this ever runs on a shared machine, PATH should be pinned to a small known-good set instead of copied wholesale.
