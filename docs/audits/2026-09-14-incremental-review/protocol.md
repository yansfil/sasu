# Live before/after measurement: impact-scoped re-review

Date: 2026-09-14 (KST evening).
Question: with real judges, does the focused round cost less than a whole re-review on a local correction, and does it still catch a planted defect that looks local but changes a shared helper, and a changed observation that contradicts a settled ground?

## Builds

| Label | Source | CLI |
| --- | --- | --- |
| baseline | `main` at `89756b5` (issue #2 merged) | `sasu.worktrees/incremental-baseline/cli/dist` |
| candidate | branch `incremental-review` at the commit this audit is recorded in | `sasu.worktrees/incremental-review/cli/dist` |

Judge routing: the code defaults, routine profile Codex `gpt-5.6-luna` at `high` with Claude `claude-sonnet-5` at `high` fallback; no `agents/config.json`; `readMaxRounds` 29 (not applied to exploring Codex calls); judge call timeout 900 s.
Codex CLI 0.154.0; Node `process.execPath` of the driver.
Both builds ran concurrently on the same machine so provider latency drift affects both alike; CPU contention is shared.

## Fixture

One disposable git project per build, generated by the driver (`run.mjs`, recorded beside this file): `src/public.mjs` (`command(n)` dispatching to `src/values.mjs` through `present` in `src/format.mjs`, plus `save`), 60 unrelated `lib/report<n>.mjs` modules, a smoke test that exercises `command(1)`, `command(2)` and one `save` failure, and a 31-requirement PRD (B1..B30 `command(n)` returns n; B31 `save` reports a store failure with the message and the value).
The baseline commit holds a stub `src/public.mjs`; the implementation is written after `implement start`, so the run-owned change set is the whole `src/` tree.

Metrics per round and role: verify wall time, lane duration, audited read commands, metered read output chars, provider token usage, verdict, findings and their requirement references, carried assessment count, and the harness's recorded round mode and reason.

## Observation limits

A first attempt of this protocol was aborted after R1/R2 because the fixture's `save` could itself throw while formatting a non-Error exception; both builds' judges reported it as a B31/D-02 defect (baseline R1 both roles, candidate R2 Code), which was a fixture defect, not a harness difference.
`save` was hardened and both builds restarted from R1; the aborted records are kept under `aborted/` and not counted.
The repair round was induced by killing one lane's judge processes from outside; a real provider outage was not observed.
The deterministic version lives in `cli/test/e2e/implement-incremental-review.test.mjs`.
Seven rounds on one fixture measure this fixture; they do not establish detection equivalence in general.
