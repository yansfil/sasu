# 전체 요구 검토 방식의 실제 실행 검증

## 결과 범위

이 문서는 workflow simplification 후보의 실제 실행과 전환 결과를 기록한다.
2026-09-08 17:10 KST 기준 중간 기록이다.
하네스 소스는 검사를 마친 후보 상태이고, 두 제품 파일럿 가운데 하나는 완료됐으며 하나는 추가 검증 승인 대기다.
전역 설치와 전체 rollout 완료를 주장하지 않는다.
행별 PASS 기록과 별도 증거 제출 절차를 없애고, 전체 요구사항과 실제 결과를 함께 검토하는 변경이다.

필수 suite 실제 실행, 현재 소스·PRD·자료의 무결성, 실행 전체 소유권, 독립 판정, 제한된 수정 반복, 사람의 권한은 유지한다.
요구사항이 34개라는 이유로 34번 CLI 명령이나 34개 증거 파일을 요구하지 않는다.
모든 요구가 검토 입력에 있다는 것은 모델의 누락 가능성이 사라진다는 뜻이 아니다.

## 동일 입력의 두 구현

제품은 로컬 링크 관리 화면 Link Pocket이다.
생성·수정·검색·태그·저장 복원·삭제 복구와 실제 저장 실패 처리를 포함한다.
공통 starter는 `0f2e1b20d644be9c897904c6900c6b9da16f7808`이며 제품 기능이 없는 동일 출발점이다.
PRD 작성자는 Codex Sol medium이고, 구현은 Codex Sol medium과 Claude Code Opus 5의 독립 native session에서 수행한다.
이는 런타임별 동작 확인을 위한 파일럿이며 모델 성능 비교 실험은 아니다.

PRD는 Behaviors 34개, Decisions 14개이며 해시는 `916b23f4663f087c42685bc4715301dad4fa97b2049d64ac4e0f2180a7eb3cf4`다.
작성 단계 지시가 제품 제한과 새 승인 조건에 섞인 부분을 한 번 교정했고, 제품 요구 34개는 유지했다.
`ready`와 `human_approval: pending`을 정직하게 보존하고 기존 사용자 원문 위임을 conversational approval로 사용했다.
가상의 인터뷰나 사용자 응답을 만들지 않았고 conversation-only PRD의 spec gate는 미실행이다.

두 구현은 제품 코드를 공유하지 않으며, 같은 PRD·starter·필수 명령을 사용한다.
포트만 충돌하지 않도록 각각 분리했다.
각 프로젝트의 실제 skill 사본과 후보 CLI를 고정하여 전역 구형 설치와 섞이지 않게 했다.
Claude는 project/local 설정만 읽는 native print session을 사용하므로 전역 설정을 사용하는 통상 실행의 확인은 설치 후 별도로 기록한다.

## 실행 결과와 비용

Claude 제품은 수정 CLI에서 최종 종합 리뷰 PASS, `complete` 상태, 전달 가능한 v5 receipt와 로컬 커밋 `6a258f845c58c1a7ba93ac7bb27a09eb16667cfc`까지 완료했다.
마지막 시도는 `f20385c1-a8a1-4c23-ac45-5b1a2386359f`이며 필수 명령이 실제 42개 브라우저 테스트를 통과했다.
같은 시도의 suite는 23.017초, 종합 리뷰는 83.109초, 전체 verify는 107.021초였다.

Codex 제품은 기존 후보에서 네 번, 수정 후보에서 한 번의 실제 FAIL을 기록해 5회 한도에 도달했다.
마지막 `007f434d-0af3-4455-99e6-8d5aaca1bd05`의 남은 문제는 초기 로딩 안내와 Retry 후 포커스 유실이었다.
두 문제의 소스를 수정하고 전체 브라우저 테스트 9개와 관련 흐름 2개를 통과했지만, 그 수정본의 독립 리뷰와 receipt는 아직 없다.
기존 실행과 실패 기록을 보존한 추가 검증 1회에 대한 명시적인 사람 승인을 요청한 상태다.
예산 초기화, 새 실행으로 우회, 가짜 승인, 실패의 PASS 치환은 하지 않았다.

현재 측정 스냅샷은 [실행별 JSON](workflow-simplification-pilot/metrics.json)에 있다.
기존 7일 감사와는 동일 조건의 속도 비교로 해석하지 않는다.

기존 7일 감사의 실질 실행 16개에는 요구 292개, 행별 check 1,307회, 통합 verify 65회가 있었다.

현재 파일럿 두 실행에는 행별 check가 없고, 필수 suite 실행과 전체 계약 리뷰만 기록된다.

최초 후보의 실제 backend smoke에서 Codex는 심은 누락과 이미지 확인을 통과했지만, 일부 사례에서 불필요한 요구별 실행 증거를 추가 요구했다.
Claude smoke는 잘못된 요구 참조 출력으로 실패했다.
제품 파일럿에서는 기존 conversational approval이 판정 입력에 빠져 불필요한 human-confirmation 출력 오류도 발생했다.
별도 correction 작업트리에서 동일 참조·human-source context와 명확한 증거 충분성 기준으로 수정했다.
수정 커밋은 `f6963672454207cbce08908cc33eaf6e74d866c7`이며 부모는 최초 후보 `c96a662`다.
수정 커밋의 tree `453c9e86609e9e1a4d9f05209b81e4325de50bcd`에서 clean build/noEmit, root 98/98, unit 447/447, E2E 120/120을 통과했다.
두 실제 판정 backend 모두 정상·중간 누락·마지막 누락·미연결·저장 실패·승인된 가정 여섯 source 사례의 정확한 blocking 기대값을 충족했고, 무관한 blocking 요구나 새 사람 승인 조건을 만들지 않았다.
Codex의 실제 이미지 자료 검토도 통과했다.
최종 smoke의 실제 호출은 Codex 8회, Claude 6회이며 fallback은 없었다.
Codex 1회 재시도는 읽기 전용 명령 검사에서 `printf`가 거부된 경우이고, 참조 schema 오류는 없었다.
이전 실패와 별도 수정 검사의 비용을 정상 최종 검사에서 지우지 않는다.
그 과정에서 정상 smoke fixture가 `Error` 외 throw 값을 처리하지 못하는 실제 결함도 발견해 fixture만 수정했으며, 심어 둔 저장 실패 변형은 유지했다.

Codex 제품의 첫 종합 리뷰는 실제 포커스 처리와 긴 선택 태그의 모바일 넘침, 필요한 runner 설정 접근 부재를 찾았다.
후속 판정은 이미 해결된 문제를 닫고, 남은 오류 포커스와 empty 상태의 0 count를 구체적으로 남겼다.
Claude 제품의 독립 브라우저 QA는 핵심 네 흐름과 실제 저장 실패, 360px 조작을 통과했다.
그 시점에는 human-source 출력 계약 오류 때문에 최종 receipt는 아직 없었다.

Codex의 네 차례 기존 후보 리뷰는 약 2.5~5분씩 걸렸고, 후속 수정 과정에서 loading 상태의 실제 paint, 지속되는 live region, 다시 읽기 안내와 undo 저장 실패 표시 같은 추가 문제도 발견했다.
이는 행별 절차 삭제가 리뷰 반복 비용까지 자동으로 없애지는 않는다는 관찰이다.
다섯 번째 이후의 허용된 검증과 최종 전달은 수정 CLI를 사용하며 이전 결과는 기존 후보의 결과로 보존한다.

Claude native print 실행이 background verify를 남기고 종료되는 문제를 한 번 복구했고, 동일 오류의 무변경 반복을 막기 위해 coordinator가 한 번 중단했다.
같은 native session과 원래 run을 유지해 interactive 실행으로 전환했으며, 모든 실패와 중단 기록을 보존한다.
이는 현재 파일럿의 실행 비용과 제약으로 기록한다.
실행 시간은 구현, 집중 검사, 브라우저 관찰, CLI verify의 필수 suite와 judge, 최종 전달로 구분한다.
동시에 진행한 작업 시간을 단순 합산해 실제 경과 시간으로 쓰지 않는다.
정상 두 구현과 고의 결함 세 변형은 각각 별도 결과로 기록한다.

## 환경 복구와 아직 실행하지 않은 단계

프로젝트 내부로 일반 파일을 복사한 skill staging은 제품의 `type: module`을 상속해 CommonJS `prd_ship.js`가 실행되지 않는 환경 결함이 있었다.
Claude 파일럿은 동일 바이트 script의 CommonJS scratch 실행으로 같은 검증·freshness·허용 파일 staging을 거쳐 로컬 전달을 끝냈다.
코디네이터가 원래 staged 경로의 실패를 재현한 뒤, 두 runtime의 staging root에 CommonJS package scope만 추가했다.
Script 바이트와 제품 소스는 유지했고 원래 documented 경로의 `ship status`도 같은 receipt에서 성공했다.
실제 설치기는 source symlink로 원래 package scope를 보존하므로 이 관찰만으로 운영 script를 개명하거나 새 설치 모드를 추가하지 않았다.

독립 브라우저 평가의 원본은 [A 보고서](workflow-simplification-pilot/qa/a/report.md)와 [B 보고서](workflow-simplification-pilot/qa/b/report.md)에 있다.
A는 확인 중 소스가 바뀌어 관찰한 소스의 주요 흐름 PASS와 최종 트리 INCONCLUSIVE를 분리했고, 표준 Browser pane 연결 실패 뒤 standalone Chromux 관찰을 했다는 제한을 남겼다.
B의 독립 관찰도 후속 두 소스 수정 이전 자료이며, 그 수정은 현재 source의 실제 42개 테스트와 종합 리뷰로 확인했다.
과거 캡처를 최신 전체 제품의 독립 PASS로 재명명하지 않는다.

심어 둔 제품 결함 세 변형은 아직 실행하지 않았다.
양쪽 원본의 완료 커밋과 receipt를 보존한 다음, 한 완료 제품에서 저장 복원 연결 제거·검색 결과 연결 제거·저장 실패 무시를 각각 하나씩 심어 새 실행에서 검증한다.
세 파생 실행은 필수 테스트를 유지하고 포트만 미리 분리해 서로 독립적으로 실행하도록 준비했다.
필수 suite에서 잡히면 suite 탐지로 기록하며 judge 탐지로 세지 않는다.

새 전역 CLI와 양쪽 runtime skill 설치, 새 세션에서 실제 skill 발견, 설치된 CLI의 작은 실제 완료와 receipt 소비도 아직 실행하지 않았다.
현재 main과 전역 CLI는 488d3cc / 0.8.0이고, 후보 파일럿만 고정된 0.9.0을 쓴다.
살아 있는 구형 schema 실행 의존성은 최신 관찰에서 발견되지 않았으며, 소유자가 불일치하는 역사적 기록은 수정·종료하지 않았다.

## 남는 한계

같은 조건의 구형 실행 baseline이 없으므로 직접 비교 속도 개선율은 산출하지 않는다.
한 제품의 두 구현과 세 결함 변형은 임의의 프로젝트에 대한 탐지율이나 무결함을 보장하지 않는다.
전체 계약 종합 검토가 놓친 결함, 불충분한 근거, 환경 실패는 해당 결과에 그대로 남긴다.
