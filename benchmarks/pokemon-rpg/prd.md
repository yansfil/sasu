# PRD: pokemon-rpg

## 1. Summary

저장소 루트에 `pokemon-rpg/` 정적 웹앱을 추가한다.
플레이어블 주인공 5명, 맵 7장(필드 4 + 전용 3), 몬스터 20종, 단일 타입 7종의 7x7 상성표, 야생전과 트레이너전 두 모드의 턴제 전투와 포획, NPC 미션 시스템, 라이벌 최종전과 엔딩까지 갖춘 완결된 2D RPG다.
런타임 npm 의존성은 0이고 번들러와 빌드 산출물이 없으며, 에셋은 전부 인라인 SVG로 직접 그린다.
devDependency로는 정적 타입체크와 playwright 두 가지만 쓴다.

이 PRD는 동시에 sasu 하네스의 표준 벤치마크 워크로드다.
목적은 (B) 무겁고 상호의존적인 작업을 끝까지 몰고 가는 능력과 (C) AC 오라클·judge가 거짓 PASS를 잡아내는 능력을 시험하는 것이다(D-04).
그래서 교차 상태 체인을 의도적으로 두 줄기 깔았다.
캐릭터 선택은 시작 파트너 → 특성 수치 → 라이벌 정체 → 최종 보스 파티까지 전파되고, 미션 완료는 맵 개방 → 세이브 → 재로드까지 전파된다.
앞 단계만 반영하고 뒤를 빠뜨리는 구현은 AC 오라클에서 즉시 드러난다.

Approval checklist:

- 스코프 경계와 non-goal (상태이상·이중타입·3단계 진화·상점/돈·난이도 선택 옵션·터치 조작·멀티플레이 제외) - §3
- 주요 기술 구조: 저장소 루트에 새 `pokemon-rpg/` 정적 앱, 런타임 의존성 0, devDependency는 타입체크와 playwright 둘뿐, 엔진/UI/데이터 3층 분리 - §5
- 콘텐츠 데이터가 PRD에 고정되어 있다는 점: 몬스터 20종 표, 7x7 상성표, 캐릭터 5명과 특성 수치, 맵 7장과 인카운터 배치 - §6 R2/R4/R6/R7
- 검증 모드 4종(build/static, automated behavior, browser/runtime, visual judgment)이 전부 required-for-done - §9.1
- 시각 품질을 스크린샷 + 읽기 전용 에이전틱 저지로 판정하는 결정 - §9.2 V5
- 스코프 축소 금지 가드레일: 시간이 부족해도 조용히 줄이지 않고, 끝까지 못 가면 그 사실을 그대로 남긴다 - §11
- 딜리버리 모드: `local` (커밋/푸시/PR 없음, `agents/config.json` 부재) - §4.3

## 2. Problem, Goal, And Users

**Problem.**
사용자는 sasu 하네스를 반복해서 시험할 표준 워크로드가 필요하다.
지금은 하네스를 고칠 때마다 "이번 변경이 실제 작업을 더 잘 처리하나"를 확인할 고정된 기준이 없다.
기존 `agents/prd/pokemon-game`은 맵 1장, 12종 로스터, NPC 트레이너전과 상태이상 non-goal이라 상태 교차가 얕고, 한 번 통과한 뒤로는 회귀 시험대 역할을 못 한다(D-01).

**Goal.**
브라우저에서 `pokemon-rpg/`를 열면 설치와 빌드 없이 즉시 플레이할 수 있고, 시작부터 엔딩까지 완주 가능하며, 전투·포획·성장·미션·영속 규칙이 확률까지 포함해 결정적으로 재현 가능하게 테스트되는 게임을 만든다.
동시에 그 규칙들이 하네스의 검증 기계로 실제 판정되도록, AC마다 기계 오라클을 붙이고 기계로 판정 불가능한 시각 품질만 별도 저지로 넘긴다.

**Users.**

- 게임을 플레이하는 사람. 데스크톱 브라우저, 키보드 조작.
- 이 저장소에서 하네스를 개선하는 사람과 에이전트. 이 PRD를 반복 실행해 하네스의 행동과 검증 능력을 관측한다(D-05).

## 3. Scope And Non-Goals

### In Scope

- **시작 흐름.** 타이틀 화면 → 주인공 5명 중 1명 선택 → 마을에서 시작.
  기존 세이브가 있으면 이어하기와 새로 시작을 함께 제시하고, 새로 시작은 확인 단계를 거친다.
- **캐릭터 5명.** 각자 고유 SVG 스프라이트, 고유 시작 파트너, 게임 계산에 실제로 반영되는 수치 특성 하나씩.
- **맵 7장.** 필드 맵 4장(숲, 동굴, 해변수로, 화산)과 전용 맵 3장(마을, 포켓몬센터 내부, 화산 정상 보스방).
  출입구로 서로 연결된 하나의 월드이며 왕복 자유.
  필드 맵은 타일셋·인카운터 테이블·야생 레벨 구간이 각각 다르고, 전용 맵은 인카운터가 없는 안전 공간이다.
- **미션 게이팅.** 동굴·해변수로·화산은 직전 필드 맵의 메인 미션을 완료해야 열린다.
  개방 상태는 세이브에 남아 새로고침 후에도 유지된다.
- **야생 인카운터.** 필드 맵의 풀숲 타일에 진입할 때마다 확률 판정.
  맵별 인카운터 테이블에서 종과 레벨을 뽑는다.
- **턴제 전투.** 기술 4슬롯(타입/위력/명중/PP), 7x7 타입 상성, STAB, 급소, 명중 판정, PP 고갈 시 대체 행동, 스피드 기반 선공, 상대 랜덤 AI.
- **전투 모드 2종.** 야생전은 도망 가능하고 포획 가능하다.
  트레이너전은 도망 불가, 상대가 2~3마리를 순차 투입, 승리 시 보상과 격파 플래그 기록, 포획 불가.
- **포획.** 몬스터볼 소모, 남은 HP 비율과 종족 포획률과 볼 보정에 캐릭터 특성 배율을 곱한 확률 판정.
  파티가 6마리로 차 있으면 거부하고 그 사실을 알린다.
- **성장.** 경험치 → 레벨업 → 스탯 재계산 → 지정 레벨 도달 시 진화 → 새 기술 습득(슬롯이 차 있으면 건너뛰고 로그로 알림).
- **NPC 3종류.** 미션 NPC(필드 맵마다 메인 미션 1개 + 사이드 미션 3~4개), 트레이너 NPC(시야 감지, 재대결 불가), 마을 NPC(회복, 아이템 지급, 안내).
- **미션 시스템.** 유형 4가지(특정 종 포획, 지정 트레이너 격파, 아이템 수집·전달, 야생 N마리 격파), 상태 4단계(미수락/진행중/완료가능/보상수령완료), 퀘스트 로그로 현재 목표 상시 확인.
- **라이벌 최종전과 엔딩.** 메인 미션 4개 완료 시 보스방 개방, 선택하지 않은 캐릭터 중 배정된 라이벌과 최종 전투, 승리 시 엔딩.
  엔딩 후에도 계속 플레이 가능하고 보스방만 재입장 불가.
- **도감.** 조우와 포획을 기록하고 12종 이상 포획 시 달성 표시.
- **아이템.** 몬스터볼과 상처약. 시작 지급, 맵의 1회성 아이템 타일, 미션 보상으로 수급.
- **전멸 복구.** 파티 전멸은 게임오버가 아니라 마을 포켓몬센터 복귀 + 전체 회복.
- **영속.** localStorage 단일 슬롯, 자동 저장, 새로고침 후 이어하기.
- **시각 완성도.** 디자인 토큰 기반 UI와 서로 구별되는 SVG 스프라이트.
- **접근성과 반응형.** 키보드만으로 완주 가능, aria-live 알림, 포커스 링, prefers-reduced-motion 존중, 360px 폭에서 가로 스크롤 없음.
- **검증 자산.** 결정적 PRNG, AC별 오라클 러너, node 회귀 스위트, playwright e2e, 주요 화면 스크린샷 캡처.

### Non-Goals

각 항목은 결과, 근거, 재검토 조건을 함께 적는다.

- **상태이상(독/마비/화상/잠듦)과 능력치 랭크 변화.**
  결과: 기술은 데미지와 명중과 PP만 다루고 변화기가 없다.
  근거: 지속 효과는 턴 파이프라인에 별도 단계를 추가하고 조합 테스트를 폭발시키는데, 전투 쪽 검증 부하는 이미 야생전/트레이너전 분기로 확보되어 있다.
  재검토: 전투 깊이를 더 요구할 때(D-33).
- **이중 타입.**
  결과: 모든 종이 단일 타입.
  근거: 상성 계산이 곱연산으로 늘면서 밸런싱 표면만 커지고 새로 증명되는 규칙이 없다.
  재검토: 로스터 확장 시(D-20).
- **3단계 진화.**
  결과: 진화 계열은 전부 2단계.
  근거: 같은 진화 규칙의 반복일 뿐이다.
  재검토: 콘텐츠 확장 시(D-21).
- **난이도 선택 옵션.**
  결과: 시작 시 쉬움/보통/어려움을 고르는 화면이 없다.
  난이도는 맵별 곡선(야생 레벨 구간, 인카운터 테이블, 트레이너 파티 강도)으로만 표현된다.
  근거: 사용자가 난이도를 별도 시스템이 아니라 맵 진행의 자연스러운 결과로 정의했다.
  재검토: 사용자가 난이도 선택을 요구할 때(D-18).
- **상점과 돈.**
  결과: 아이템은 시작 지급, 맵의 1회성 타일, 미션 보상으로만 들어온다.
  근거: 경제 시스템은 밸런싱 표면만 새로 만든다.
  재검토: 아이템 수급이 부족하다고 판명될 때(D-31).
- **온스크린 터치 조작.**
  결과: 모바일에서 레이아웃은 깨지지 않지만 키보드가 없으면 조작할 수 없다.
  근거: 온스크린 D-pad는 별도 입력 계층과 별도 QA 레인을 요구한다.
  재검토: 모바일 플레이 요구가 나올 때(D-40).
  §9.3에서 사용자에게 명시적으로 확인받는다.
- **사운드와 음악.**
  결과: 무음 플레이.
  근거: 오디오 에셋과 자동재생 정책 처리가 규칙 구현보다 커진다.
  재검토: 사용자가 효과음을 요청할 때.
- **통신 교환, 멀티플레이, 온라인 랭킹.**
  결과: 완전 오프라인 1인 플레이.
  근거: 서버·인증·개인정보 경계를 도입한다.
- **다중 세이브 슬롯과 세이브 내보내기·가져오기.**
  결과: 슬롯 1개.
  근거: 슬롯 관리 UI가 추가 상태를 만든다.
- **빌드 도구, 번들러, 프레임워크, 런타임 npm 의존성, 외부 이미지·폰트·CDN 에셋, 생성형 이미지.**
  결과: 파일을 그대로 서빙해 실행하는 정적 앱이며 스프라이트와 타일은 인라인 SVG와 CSS로 그린다.
  근거: 생성형 이미지는 외부 런타임 왕복과 실행 간 비재현성으로 벤치마크를 오염시킨다(D-11).
  devDependency로 타입체크와 playwright를 두는 것은 이 non-goal의 예외이며, zero-dependency 가드레일은 런타임 의존성에만 적용된다(D-07, D-09).
- **세션 분석 도구, 계측 코드, 벤치마크 리포트 생성기, 벤치마크 실행 스킬.**
  결과: 이 앱은 자기 실행 시간을 재거나 리포트를 만들지 않는다.
  근거: 분석과 실행 자동화는 이 PRD 실행이 끝난 뒤 별건으로 다룬다(D-08, D-49).

## 4. Pre-Work And Required Decisions

### 4.1 Pre-Work Before Implementation

`None required.`
계정, 자격증명, 결제, 외부 서비스, 사용자만 가진 에셋이 전혀 필요 없다.
스프라이트와 타일은 인라인 SVG로 구현하므로 에이전트가 전부 만들 수 있고, devDependency 두 개는 공개 npm 레지스트리에서 설치된다.

### 4.2 Human Decisions Before PRD Approval

- 스코프와 non-goal 승인(§3). 특히 상태이상 제외와 터치 조작 제외.
- 콘텐츠 데이터 고정 승인(§6 R2/R4/R6/R7). 몬스터 20종, 캐릭터 5명, 맵 7장이 PRD에 표로 고정되어 있으며 구현이 임의로 바꿀 수 없다.
- 검증 모드 4종이 전부 required-for-done인 것 승인(§9.1).
- 시각 품질을 에이전틱 저지로 판정하는 결정 승인(§9.2 V5).

### 4.3 Decision Traceability For Fidelity Review

소스는 `agents/interview/pokemon-rpg/qa-log.md`이며 결정 레지스터 50행(D-01~D-50)을 담고 있다.

**사용자 결정 (user decision)**

- D-04 목적을 (B) 능력 한계 테스트 + (C) 검증 기계 시험대로 확정. → §1, §2 Goal, §9 검증 강도.
- D-05 실행 후 세션을 분석해 리포트를 낸다. → §2 Users(맥락), 분석 자체는 §3 non-goal.
- D-08 세션 분석 도구를 PRD 범위 밖으로 분리. → §3 non-goal.
- D-09 런타임 의존성 0 유지 + devDependency로 타입체크와 playwright 추가. → §5, §9.1.
- D-10 시각적 완성도를 명시 요구사항으로. → R19, AC24, V5.

## 5. Major Technical Structure Changes

- 저장소 루트에 새 최상위 디렉터리 `pokemon-rpg/`를 추가한다.
  자족적 정적 웹앱이며 기존 harness 코드(`cli/**`, `skills/**`, `tests/**`)와 어떤 방향으로도 의존하지 않는다.
- 3층 분리를 강제한다.
  `src/data/`는 순수 데이터(종·타입 상성·기술·캐릭터·맵·인카운터·미션 정의)만 담고 로직을 담지 않는다.
  `src/engine/`은 DOM을 참조하지 않는 순수 ES 모듈로 전투·포획·성장·월드·퀘스트·세이브 규칙을 구현한다.
  `src/ui/`만 DOM과 이벤트를 다룬다.
  이 경계 덕분에 규칙 전체가 브라우저 없이 `node --test`로 검증 가능하다(D-03 관행 승계).
- 모든 확률은 주입 가능한 시드 PRNG 하나를 통과한다.
  엔진 진입점은 PRNG 인스턴스를 인자로 받고 전역 `Math.random`을 직접 호출하지 않는다.
  이 훅은 UI에 새 사용자 흐름을 추가하지 않으며, 시드를 고정하면 인카운터·명중·급소·데미지 난수·포획·AI 선택이 전부 재현된다(D-27).
- 세이브는 localStorage 단일 키에 버전 필드를 가진 JSON 하나로 저장한다.
  저장 대상은 선택 캐릭터, 파티, 현재 맵과 좌표, 인벤토리, 도감, 미션 상태, 트레이너 격파 플래그, 획득한 아이템 타일, 맵 개방 상태, 엔딩 달성 여부다(D-30).
- 테스트 전용 `package.json`을 둔다.
  `dependencies`는 비어 있어야 하고 `devDependencies`에는 타입체크 도구와 playwright만 들어간다.
  스크립트는 `check`(타입체크), `test`(node 회귀 스위트), `ac`(AC 오라클 러너), `e2e`(playwright), `serve`(정적 서버)다.
- AC 오라클 러너는 `tools/ac.mjs` 하나로 두고 저장소 루트에서 `node pokemon-rpg/tools/ac.mjs <AC-ID>`로 직접 실행 가능해야 한다.
  npm 스크립트 경유나 `bash -c` 래퍼를 요구하지 않는다(D-45).
  러너는 워크스페이스를 수정하지 않는다.
- 브라우저 검증의 앱 기동은 테스트가 스스로 책임진다.
  playwright 설정의 `webServer`가 `node pokemon-rpg/tools/serve.mjs`를 띄우고 테스트 종료 시 정리하므로, 검증자가 별도로 서버를 먼저 올려둘 필요가 없다.
  이 구조가 chromux 같은 공유 데몬을 쓰지 않아도 되는 이유다(D-07).

레이아웃:

```text
pokemon-rpg/
  index.html
  package.json          # dependencies 비어 있음, devDependencies 2개
  tsconfig.json         # checkJs 기반 타입체크 설정
  styles/               # tokens.css, app.css
  src/
    data/               # species, types, moves, characters, maps, encounters, quests
    engine/             # rng, battle, capture, growth, world, quest, save
    ui/                 # screens, input, sprites
  test/                 # node --test 회귀 스위트
  e2e/                  # playwright 시나리오와 스크린샷 캡처
  tools/                # ac.mjs, serve.mjs
```

### 6.2 Requirement List

- R1. **정적 웹앱 셸.** `pokemon-rpg/index.html`을 로컬 정적 서버로 열면 설치나 빌드 없이 게임이 뜬다.
  런타임 npm 의존성, 번들러, 빌드 산출물, 외부 네트워크 요청이 없고 콘솔 에러가 발생하지 않는다.
- R2. **플레이어블 캐릭터 5명.** 타이틀에서 시작하면 표 A의 5명이 각자 SVG 스프라이트, 이름, 특성 설명, 시작 파트너와 함께 제시되고 그중 1명을 고른다.
  선택한 캐릭터와 시작 파트너는 즉시 세이브에 기록된다.
  별도의 스타터 선택 화면은 없다.
- R3. **오버월드 이동.** 4방향 이동(방향키와 WASD), 충돌 타일 차단, 플레이어를 따라가는 카메라 뷰포트를 제공한다.
  타일 종류는 길(통행), 풀숲(통행 + 인카운터 판정), 벽·물·바위(충돌), 출입구(맵 전환), 아이템(1회성 획득), 표지판(안내 텍스트), 회복(포켓몬센터)이다.
- R4. **맵 7장과 맵 타입.** 표 B의 7장을 제공하며 필드 맵 4장과 전용 맵 3장으로 나뉜다.
  난이도는 표 B의 레벨 구간, 맵별 인카운터 테이블, 트레이너 파티 강도로만 표현되고 별도의 난이도 선택 화면은 없다.
- R5. **미션 게이팅과 맵 전환.** 출입구 타일에 올라서면 맵이 전환된다.
  아직 열리지 않은 맵의 출입구에서는 전환이 거부되고 어떤 미션을 깨야 열리는지 안내한다.
  맵 개방 상태는 세이브에 영속되어 새로고침 후에도 유지된다.
- R6. **몬스터 20종과 인카운터.** 표 C의 20종을 제공한다.
  맵별 인카운터 테이블은 표 C의 출현 맵과 표 B의 레벨 구간을 따르며 각 종에 가중치가 붙는다.
  희귀종 뮤는 화산에서만 다른 종보다 현저히 낮은 가중치로 출현하고, 전용 맵에서는 인카운터가 발생하지 않는다.
- R7. **턴제 전투 규칙.** 표 D의 7x7 상성표를 구현한다.
  데미지는 `((2 * Lv / 5 + 2) * 위력 * 공격 / 방어) / 50 + 2`에 STAB 1.5, 타입 상성, 급소 1.5(확률 1/16), 난수 0.85~1.00을 곱하고, 아군이 주는 데미지에는 표 A의 캐릭터 배율이 추가로 곱해진다.
  행동 순서는 스피드 기반 선공 판정이다.
  기술은 몬스터당 4슬롯이며 각각 타입, 위력, 명중, PP를 가진다.
  명중 판정에 실패하면 데미지가 0이고 PP는 소모된다.
  PP가 0인 기술은 선택할 수 없고 모든 기술의 PP가 0이면 대체 행동으로 넘어간다.
  PP는 포켓몬센터에서 회복된다.
- R8. **전투 모드 분기.** 야생전은 도망(스피드 기반 확률)과 포획이 가능하다.
  트레이너전은 도망과 포획이 모두 불가능하고, 상대가 2~3마리를 순차 투입하며, 승리하면 보상 아이템을 받고 격파 플래그가 기록되어 다시 싸울 수 없다.
  격파 플래그는 세이브에 영속된다.
- R9. **포획.** 몬스터볼을 소모하고 `남은 HP 비율 x 종족 포획률 x 볼 보정 x 캐릭터 특성 배율`로 성공 확률을 계산한다.
  성공하면 파티에 추가되고 도감의 포획 기록이 갱신되며, 실패하면 턴이 소모된다.
- R10. **파티 관리.** 파티는 최대 6마리다.
  가득 찬 상태에서 포획을 시도하면 거부하고 그 사실을 알린다.
  파티 메뉴에서 순서 변경과 각 개체의 레벨·HP·기술·PP 확인이 가능하고, 전투 중 교체는 턴을 소모한다.
- R11. **아이템과 인벤토리.** 몬스터볼과 상처약을 제공한다.
  시작 인벤토리는 몬스터볼 10개(민들레 선택 시 20개)와 상처약 3개다.
  맵의 아이템 타일에서 1회성으로 추가 획득하며 획득 여부는 세이브에 남아 재획득이 불가능하고, 미션 보상으로도 지급된다.
  상처약 회복량에는 캐릭터 특성 배율이 곱해지고, 포켓몬센터 타일에서 파티 전체의 HP와 PP가 회복된다.
- R12. **성장과 진화.** 전투 승리 시 경험치를 얻고 레벨업하면 스탯이 재계산된다.
  표 C의 진화 레벨에 도달하면 진화하며 종이 바뀌고 스탯이 재계산된다.
  레벨업 시 새 기술을 습득하고, 기술 슬롯 4개가 모두 차 있으면 습득을 건너뛰고 그 사실을 전투 로그에 남긴다.
- R13. **NPC와 미션 시스템.** 미션 NPC는 맵당 메인 미션 1개와 사이드 미션을 제공하며 미션 유형은 특정 종 포획, 지정 트레이너 격파, 아이템 수집·전달, 야생 N마리 격파 4가지다.
  필드 맵 4장(숲·동굴·해변수로·화산) 각각에 메인 미션 1개와 사이드 미션 3~4개를 배치한다.
  따라서 메인 미션은 총 4개, 사이드 미션은 총 12~16개이며 4가지 유형이 모두 최소 1회 쓰인다.
  미션 상태는 미수락, 진행중, 완료가능, 보상수령완료 4단계로 전이하며 세이브에 영속되고, 이미 보상을 받은 미션은 다시 보상을 주지 않는다.
  트레이너 NPC는 시야 안에 플레이어가 들어오면 전투를 시작하고, 마을 NPC는 회복·아이템 지급·안내 대사를 제공한다.
- R14. **퀘스트 로그.** 메뉴에서 퀘스트 로그를 열면 수락한 모든 미션의 현재 상태, 목표, 남은 진행량을 확인할 수 있다.
- R15. **라이벌 최종전과 엔딩.** 메인 미션 4개를 모두 완료하면 화산 정상 보스방이 열린다.
  라이벌은 플레이어가 선택하지 않은 캐릭터 중 순환 규칙으로 배정되며, 순서는 지우 → 이슬이 → 웅 → 그린 → 민들레 → 지우이고 라이벌은 선택한 캐릭터의 다음 순번이다.
  라이벌 파티는 3마리이며 그 라이벌 시작 파트너의 최종 진화형과 보스 전용 종 파이어를 반드시 포함한다.
  승리하면 엔딩 화면이 나오고 엔딩 달성이 세이브에 기록되며, 엔딩 후에도 세이브를 유지한 채 계속 플레이할 수 있고 보스방만 재입장이 불가능하다.
- R16. **도감.** 조우한 종과 포획한 종을 각각 기록하고 목록으로 보여준다.
  서로 다른 12종 이상을 포획하면 달성 표시를 띄우며 이 달성은 엔딩 조건과 독립이다.
- R17. **세이브와 이어하기.** localStorage 단일 슬롯에 저장하고 맵 이동·전투 종료·미션 상태 변화 시 자동 저장한다.
  새로고침하면 이어하기가 가능하며 저장 대상은 §5에 명시한 항목 전체다.
  메뉴의 새로 시작은 되돌릴 수 없으므로 확인 단계를 거치고, 취소하면 아무것도 지워지지 않는다.
- R18. **전멸 복구.** 파티가 전멸하면 게임오버나 진행 삭제가 아니라 마을 포켓몬센터로 복귀하고 파티가 전체 회복된다.
  선두가 기절하면 살아있는 개체로 교체를 요구한다.
- R19. **시각 완성도.** 타이포그래피·컬러·스페이싱·라운드·섀도의 디자인 토큰을 먼저 정의하고 모든 화면이 그 토큰만 사용한다.
  캐릭터 5명, 몬스터 20종, 타일 종류, UI 크롬을 인라인 SVG와 CSS로 그린다.
  몬스터 20종은 서로 시각적으로 구별 가능해야 하며 같은 도형에 색만 바꾼 수준은 요구를 충족하지 않는다.
  외부 이미지 파일, 생성형 이미지, 외부 에셋 팩, CDN 폰트를 쓰지 않는다.
- R20. **접근성.** 키보드만으로 시작부터 엔딩까지 완주할 수 있고, 조작은 방향키와 WASD로 이동, Z와 Enter로 확인, X와 Esc로 취소·메뉴다.
  전투 행동과 판정 결과, 미션 상태 변화, 맵 전환이 텍스트 로그로 남고 `aria-live` 영역으로 전달된다.
  포커스 링이 보이고 `prefers-reduced-motion: reduce`에서 애니메이션이 비활성화되며 조작 안내가 상시 노출된다.
- R21. **반응형과 성능.** 뷰포트 폭 360px에서 모든 화면이 가로 스크롤 없이 표시된다.
  맵 전환과 전투 진입은 각각 500ms 이내에 완료된다.
  오버월드 이동은 60fps를 구현 목표로 삼되 프레임률은 기계 판정 대상이 아니며 체감 부드러움은 HV5에서 사람이 확인한다.
- R22. **결정적 PRNG.** 인카운터 발생, 인카운터 종 추첨, 명중, 급소, 데미지 난수, 포획, 도망, 상대 AI 선택이 모두 주입된 PRNG를 통과한다.
  같은 시드와 같은 입력이면 같은 결과가 나오고, 엔진은 전역 `Math.random`을 호출하지 않는다.
- R23. **검증 자산.** `node --test` 회귀 스위트, AC별 오라클 러너, playwright e2e 시나리오, 주요 화면 스크린샷 캡처, 정적 서버 스크립트를 제공한다.
  AC 오라클 러너는 저장소 루트에서 `node pokemon-rpg/tools/ac.mjs <AC-ID>`로 실행되며 PASS면 exit 0, FAIL이면 비영 종료하고 파일을 쓰지 않는다.

## 7. Acceptance Criteria

- AC1. 저장소가 타입체크를 통과하고 모든 소스 모듈이 파싱·로드된다. Check: `node pokemon-rpg/tools/ac.mjs AC1`
- AC2. 타이틀에서 시작하면 R2 표의 캐릭터 5명이 각자 시작 파트너와 특성 설명을 달고 제시되며, 5명 전원이 선택 가능하다. Check: `node pokemon-rpg/tools/ac.mjs AC2`
- AC3. 캐릭터 5명 각각에 대해 특성 수치가 실제 계산에 반영된다. 같은 시드와 같은 상황에서 지우는 인카운터 확률이 x1.20, 이슬이는 포획 확률이 x1.20, 웅은 상처약 회복량이 x1.30, 그린은 데미지가 x1.10, 민들레는 시작 몬스터볼이 20개다. Check: `node pokemon-rpg/tools/ac.mjs AC3`
- AC4. 캐릭터를 선택하면 선택 캐릭터와 R2 표의 해당 시작 파트너가 세이브에 기록되고, 5명 각각에 대해 파트너 종이 정확히 일치한다. Check: `node pokemon-rpg/tools/ac.mjs AC4`
- AC5. 몬스터 로스터가 정확히 20종이고 R6 표와 종·타입·분류·진화 레벨·출현 맵이 전부 일치하며, 진화 계열 6개(12종), 단독 6종, 보스 전용 1종, 희귀종 1종의 분류 개수가 맞고, 모든 종이 단일 타입이다. Check: `node pokemon-rpg/tools/ac.mjs AC5`
- AC6. 맵이 정확히 7장이고 R4 표와 이름·타입·야생 레벨 구간·진입 조건이 일치하며, 필드 4장과 전용 3장으로 나뉜다. Check: `node pokemon-rpg/tools/ac.mjs AC6`
- AC7. 전용 맵 3장에서는 풀숲 진입을 반복해도 인카운터가 0건 발생하고, 필드 맵 4장에서는 각 맵의 인카운터 테이블에 없는 종이 단 한 번도 출현하지 않는다. 희귀종 뮤는 화산에서만 출현한다. Check: `node pokemon-rpg/tools/ac.mjs AC7`
- AC8. 게임 시작 직후 동굴·해변수로·화산 출입구는 전환을 거부하고 필요한 미션을 안내한다. 직전 필드 맵의 메인 미션을 완료하면 해당 맵의 전환이 허용된다. Check: `node pokemon-rpg/tools/ac.mjs AC8`
- AC9. 맵 개방 상태가 세이브에 기록되고, 세이브를 직렬화한 뒤 복원하면 개방 상태가 그대로 유지된다. Check: `node pokemon-rpg/tools/ac.mjs AC9`
- AC10. 7x7 타입 상성표 49개 조합의 배율이 R7 표와 전부 일치하고, x0 배율이 존재하지 않는다. Check: `node pokemon-rpg/tools/ac.mjs AC10`
- AC11. 시드를 고정하면 동일한 전투 입력이 동일한 데미지·급소·명중·행동 순서를 산출하고, 데미지 값이 R7 공식과 STAB·상성·급소·난수·캐릭터 배율을 반영한 기대치와 일치한다. Check: `node pokemon-rpg/tools/ac.mjs AC11`
- AC12. PP가 0인 기술은 선택할 수 없고, 모든 기술의 PP가 0이면 대체 행동으로 넘어가며, 명중 실패 시 데미지가 0이면서 PP는 소모된다. 포켓몬센터에서 PP가 회복된다. Check: `node pokemon-rpg/tools/ac.mjs AC12`
- AC13. 야생전에서는 도망과 포획이 가능하고, 트레이너전에서는 도망과 포획이 모두 거부되며 그 사실이 로그에 남는다. Check: `node pokemon-rpg/tools/ac.mjs AC13`

## 10. Risks And Open Decisions

- **R-1. 워크로드가 한 번의 실행으로 완주되지 않을 수 있다.**
  이것은 결함이 아니라 의도된 측정 조건이다(D-42).
  스코프를 줄여 완주하는 것은 금지되며, 끝까지 가지 못하면 어디까지 갔는지를 그대로 보고한다.
- **R-2. 시각 완성도는 기계로 판정할 수 없다.**
  V5의 읽기 전용 판정이 유일한 자동 방어선이며 최종 취향 판단은 HV1이 맡는다.
  이 축에서 기계 오라클이 전부 통과했는데 결과물이 못 봐줄 가능성이 이 워크로드가 노리는 검증 구멍이다(D-28).
- **R-3. 확률 규칙은 시드 없이는 자동 검증이 불가능하다.**
  R22의 PRNG 주입이 깨지면 AC3, AC7, AC11, AC13의 오라클이 전부 무의미해진다.
  엔진이 전역 `Math.random`을 호출하지 않는다는 것 자체를 AC11 오라클이 함께 확인한다.
- **R-4. 콘텐츠 데이터 물량이 크다.**
  20종 x 7타입 x 맵별 가중치 x 기술 테이블을 옮기는 과정에서 표와 구현이 어긋날 수 있다.
  AC5, AC6, AC10, AC17이 표와 구현의 일치를 직접 대조한다.
- **R-5. 원작 계열 명칭 사용(D-13).**
  개인 학습·벤치마크용이며 배포하지 않는다는 전제이고 에셋은 전부 직접 그린 SVG다.
  외부 공개 시 재검토가 필요하다.
- **운영 조건 (PRD 산출물이 아니라 실행 시 지켜야 할 사전 합의).**
  verify 게이트가 FAIL이면 override하지 않는다(D-46).
  이전 실행은 FAIL을 override해 complete로 만들었고, 같은 일이 반복되면 완주 결과가 통과인지 은폐인지 구분되지 않는다.
  실행은 승인 경로로 건다(D-47).
  이 PRD는 승인 후 `agents/` 밖의 벤치마크 원본으로 복사해 보관하고, 실행할 때마다 새 슬러그로 복사해 돌린다(D-48).
- **측정 한계 (알려진 사실, 이 PRD로 해결하지 않음).**
  이전 실행 실측에서 wall-clock의 98.1%가 미귀속이었다(D-43).
  단계별 소요시간과 병목은 현재 하네스 계측으로 관측되지 않으며 세션 트랜스크립트 사후 재구성에 의존한다.
  계측 개선과 벤치마크 실행 스킬은 첫 실행 이후 별건으로 다룬다(D-49).

## 11. Implementation Guardrails

- **스코프를 줄이지 않는다.**
  시간이 부족하거나 작업이 크다는 이유로 몬스터 수, 맵 수, 캐릭터 수, 미션 수, 검증 자산을 임의로 축소하지 않는다.
  §6의 표는 고정 계약이다.
  완주가 어려우면 줄이지 말고 어디까지 했는지를 보고한다(D-42).
- 승인된 요구사항 밖으로 스코프를 확장하지 않는다.
  상태이상, 이중 타입, 3단계 진화, 상점·돈, 난이도 선택 옵션, 터치 조작, 사운드, 멀티플레이를 추가하지 않는다.
- §5의 3층 분리와 PRNG 주입 구조를 바꾸지 않는다.
  엔진에서 DOM을 참조하거나 전역 `Math.random`을 호출하지 않는다.
- 런타임 npm 의존성, 번들러, 프레임워크, 외부 이미지·폰트·CDN 에셋, 생성형 이미지를 도입하지 않는다.
  devDependency는 타입체크 도구와 playwright 두 가지로 제한한다.
- 자동 브라우저 검증에 chromux를 쓰지 않는다.
  chromux는 대화형 QA 전용이며 커밋되는 테스트와 오라클은 테스트가 직접 띄우고 정리하는 도구를 쓴다(D-07).
- `pokemon-rpg/`와 `agents/` 밖의 파일을 수정하지 않는다.
  특히 `cli/**`, `skills/**`, `tests/**`는 다른 세션이 동시 작업 중일 수 있으므로 건드리지 않는다.
- AC 오라클은 워크스페이스를 수정하지 않는다.
  오라클과 검증 명령은 반복 실행해도 같은 결과를 내야 한다.
- 세션 분석 도구, 계측 코드, 리포트 생성기, 벤치마크 실행 스킬을 만들지 않는다(D-08, D-49).
- 실패한 검증을 통과로 표시하지 않는다.
  블록된 항목은 블록된 채로 보고한다.

## 12. Implementation Result Report Contract

구현 에이전트는 다음을 보고한다.

- 상태: `Done`, `Partially Done`, `Blocked` 중 하나.
  `Partially Done`이면 §6의 어떤 표 항목이 빠졌는지 개수와 함께 명시한다.
- 사용자에게 보이는 변경: 실행 방법(정적 서버 기동 명령과 URL)과 플레이 흐름 요약.
- 주요 변경 모듈과 데이터 형태: `src/data`, `src/engine`, `src/ui`의 모듈 목록과 세이브 스키마.
- 승인된 기술 구조(3층 분리, PRNG 주입, 의존성 0, devDependency 2개)를 따랐는지.
- T1~T10 각각의 완료 상태.
- R1~R23, AC1~AC31, V1~V5의 커버리지.
- 모드별 검증 증거: 타입체크 로그, `node --test` 결과와 테스트 건수, AC 오라클 전량 실행 결과, playwright 결과, 등록된 스크린샷 아티팩트 경로 목록.
- 추가하거나 갱신한 자동 테스트와 각각이 막는 회귀 위험.
- 딜리버리: `local` 모드이므로 커밋·푸시·PR 없음.
- 편차: 승인 없이 바꾼 것, 축소한 것, 블록된 것.
  스코프 축소가 있었다면 반드시 편차로 기록한다.
- 남은 사람 확인 항목: HV1~HV4.
- 완료하지 못한 항목과 후속 후보.
