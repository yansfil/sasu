# PRD: pokemon-rpg

## Goal

저장소 루트의 `pokemon-rpg/`에 설치와 빌드 없이 플레이할 수 있는 완결된 2D 브라우저 RPG를 만든다.
플레이어블 주인공 5명, 맵 7장, 몬스터 20종, 단일 타입 7종, 야생전과 트레이너전, 포획과 성장, NPC 미션, 라이벌 최종전과 엔딩을 포함한다.
고정 게임 규칙은 확률까지 재현 가능해야 하며, 전체 요구사항을 독립 종합 리뷰의 입력으로 보존한다.
이 PRD와 benchmark.json은 새 환경에서 실행하는 고정 benchmark case다.

## Non-goals

각 항목은 결과, 근거, 재검토 조건을 함께 적는다.

- **상태이상과 능력치 랭크 변화.**
  결과는 데미지, 명중, PP만 다루는 기술 체계다.
  지속 효과가 턴 파이프라인과 조합 검증을 크게 늘리므로 제외한다.
  전투 깊이를 더 요구할 때 재검토한다(D-33).
- **이중 타입.**
  모든 종은 단일 타입이다.
  상성 계산과 밸런싱 표면만 늘리고 새 규칙을 증명하지 않으므로 제외한다.
  로스터를 확장할 때 재검토한다(D-20).
- **3단계 진화.**
  진화 계열은 2단계다.
  동일한 진화 규칙의 반복이므로 제외한다.
  콘텐츠 확장 시 재검토한다(D-21).
- **난이도 선택 옵션.**
  난이도는 맵별 야생 레벨, 인카운터, 트레이너 파티 곡선으로 표현한다.
  별도 난이도 시스템을 원하지 않는 사용자 결정을 따른다(D-18).
- **상점과 돈.**
  아이템은 시작 지급, 1회성 타일, 미션 보상으로 얻는다.
  경제 시스템이 별도 밸런싱 표면을 만들기 때문에 제외한다(D-31).
- **온스크린 터치 조작.**
  360px에서 레이아웃은 유지하지만 키보드가 없으면 플레이할 수 없다.
  별도 입력 계층이 필요하므로 제외한다.
  모바일 플레이 요구가 생기면 재검토한다(D-40).
- **사운드와 음악.**
  무음 플레이며 오디오 에셋과 자동재생 정책을 다루지 않는다.
- **멀티플레이, 통신 교환, 온라인 랭킹.**
  서버, 인증, 개인정보 경계를 만들지 않는 오프라인 1인 게임이다.
- **다중 세이브 슬롯과 세이브 내보내기·가져오기.**
  로컬 슬롯 하나만 제공한다.
- **번들러, 프레임워크, 런타임 npm 의존성, 외부 이미지·폰트·CDN 에셋, 생성형 이미지.**
  그대로 서빙하는 정적 앱과 직접 그린 SVG·CSS만 사용한다.
  정적 타입 검사와 자동 브라우저 검증을 위한 개발 도구는 이 제한의 예외다(D-07, D-09, D-11).
- **세션 분석 도구, 계측 코드, 벤치마크 리포트 생성기, 벤치마크 실행 스킬.**
  실행 후 분석과 벤치마크 자동화는 별도 작업이다(D-08, D-49).

## Technical structure

- 저장소 루트에 기존 harness와 런타임 의존 관계가 없는 자족적 정적 웹앱 경계를 추가한다.
- 고정 콘텐츠 정의, 결정 가능한 게임 규칙, 브라우저 입출력의 책임을 분리한다.
  구체 모듈 수와 파일 배치는 구현 계획이 선택하되, 규칙 검증이 DOM 조작을 요구하지 않는 경계는 보존한다.
- 모든 확률 의존 동작은 같은 시드와 입력으로 같은 결과를 내는 제어 가능한 무작위성 경계를 통과한다.
- 영속은 브라우저 localStorage의 단일 슬롯으로 제한한다.
  저장 형식은 버전 변화와 손상된 데이터에 안전하게 대응할 수 있어야 하지만 키 이름과 스키마 모듈은 구현 계획이 정한다.
- 자동 브라우저 검증은 실행 때마다 자체 앱 서버를 시작하고 종료하며 공유 브라우저 데몬에 의존하지 않는다.

## Risks

- 범위가 큰 workload이며 한 실행에서 끝나지 않으면 빠진 요구와 원인을 그대로 보고한다.
  캐릭터, 맵, 몬스터, 타입, 미션을 임의로 줄이지 않는다.
- 시각적 겹침, 잘림, 대비와 구별 가능성은 실제 화면 자료와 종합 리뷰가 확인한다.
  재미, 인카운터 빈도, 전투 템포, 난이도 곡선, 엔딩까지 걸리는 시간, 미션 동선, 60fps 체감과 최종 미적 취향은 D-28과 D-41에 따라 완료 후 사람이 판단할 수 있다.
- 결정적 확률 경계나 고정 콘텐츠 표가 잘못되면 여러 동작이 함께 틀릴 수 있으므로 실제 입력과 경계값으로 확인한다.
- 개인 학습과 benchmark용 비공개 팬 구현이며 에셋은 직접 그린다.
  공개와 배포에는 별도 재검토가 필요하다.
- 고정 표 A-D의 값과 단일 수치 캐릭터 특성은 기존 승인 범위다.
  정확한 저장 키, 모듈과 실행 명령은 구현자가 결정한다.
- 실제 브라우저 관찰 없이 화면·키보드·영속 동작을 확인했다고 보고하지 않는다.
  공유 브라우저 데몬은 자동 테스트의 실행기가 아니다.
- 제품 변경은 `pokemon-rpg/`에 한정하고 기존 harness 소스는 변경하지 않는다.
- 벤치마크 원본은 `agents/` 밖에 보관하고 실행마다 복사한다.
  실행 시간과 호출 수는 실제 기록으로 계산하며 앱에 측정 도구를 추가하지 않는다.
- 완료 보고는 실행 방법, 구현 결과, 실제 테스트 명령·환경·결과, 관찰 자료, 종합 리뷰, 미해결 문제와 사람 판단을 설명한다.
  요구마다 성공 표를 만들지 않으며 미실행·오류·blocked를 완료로 표현하지 않는다.
- 딜리버리는 local이며 완료 기록의 현재 입력과 전달 가능 여부를 확인한 뒤 로컬 커밋한다.
  푸시와 PR은 이 workload의 범위에 없다.
